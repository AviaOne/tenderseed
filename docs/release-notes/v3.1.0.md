This release changes one behaviour, on gno.land only: what one answer to a
request for addresses carries. The Cosmos side is untouched.

## Fixed

- **On gno.land, an answer carries at most thirty addresses.** Since gno
  v1.5.0 a node refuses a discovery answer carrying more than thirty addresses,
  the core's own ceiling, and keeps none of them. A v3.0.0 seed answered with
  every fresh address it held, up to the selection size the Cosmos side serves,
  so on a chain running v1.5.0 or later any of its answers above thirty taught
  the node that asked nothing at all. A node whose only source was that seed
  never started exchanging peers. Each answer is now drawn from the whole fresh
  set, shuffled and spread over network ranges as before, then cut to thirty,
  so successive requesters receive different parts of that set. What the seed
  holds, verifies and calls fresh does not change.

## Updating

Only the binary is replaced. Node identity, configuration and address book are
untouched. No configuration key was added, removed or renamed, and no metric
series changed. See the update procedure in the README.
